# Handoff (state on 2026-11-21, evening)

## 1. What this project is
A **work-health coach** for the Logitech hackathon. A camera/microphone notices a situation (you stopped blinking, you speak too fast, someone is behind you ...)
and the feedback comes through **MX Master 4 haptics**, the **MX Keypad screen**, and a small **pixel owl / snail on the screen**.
Judges want it **user-friendly and not annoying**, so every alert goes through a notification policy the user can tune (presets, buzz strength, snooze).
Team split so far: one person built the feedback side (plugin, Keypad, overlay, policy, launcher); a teammate builds camera/audio detection (speech pace; Windows camera tests).

## 3. Architecture
```
 LogiInsight camera --(USB UVC + SSH JSON)--> blink_monitor.py --+
 microphone ---------------------------------> pace_monitor.py --+--> CoachClient (brain/src/brain/bridge/client.py)
                                                                           | HTTP POST/GET, 127.0.0.1:8787
                                                                           v
   Logi Options+ / Plugin Service  [C# plugin WorkHealthCoach]
     LocalServer.cs -> TriggerBus -> WorkHealthCoachPlugin.OnRaw -> NotificationPolicy.Decide -> OnDecided
        -> HapticPlayer.Play     -> PluginEvents.RaiseEvent("pulseSoft"...) -> eventMapping.yaml -> MX Master 4 waveform
        -> SessionState + KeypadScreen (CoachScreenFolder, PixelScene) -> MX Keypad
        -> SessionState.OnOverlay -> GET /overlay  <--poll 4x/s--  overlay/overlay.py (PySide6 window: owl / snail)
```
Everything is local (localhost only, no network). Settings file: `settings.json` in `~/Library/Application Support/WorkHealthCoach/` (Windows `%APPDATA%\WorkHealthCoach\`).

## 5. Decisions already made
- **Scope = feedback to triggers.** Detection feeds a fixed trigger contract (`docs/TRIGGER_CONTRACT.md`); alerts are not hard-wired to a camera.
- **No praise / positive buzzes.** Only notify when it matters; everything tunable (judging criterion: friendly, not ignored).
- **Animals:** snail = slow down, owl = blink. Cute pixel style (generated by `scripts/gen_sprites.py`). The idea list also mentions a bunny; not drawn.
- **Keypad:** one big pixel-art "Coach screen" (all 9 keys as one picture); reminders take over the whole Keypad only when needed (eye until you blink).
- **Pace metric:** syllables/s from the teammate's algorithm (fast >= 5.0, ok < 4.3; ~200 wpm by our rough x40 conversion, the research suggests ~170 wpm: tune with `--fast-rate`).
- **Blink logic:** reminder after N s without a blink (default 8 s, demo 5-6 s), NOT based on an unproven "blinks per hour" claim. A blink needs >= 2 closed results and a deep dip; closures up to 2.5 s count.
- Owl/screen-share hiding, Zoom tests: **out of scope** for the prototype.
- The user asked: do not change working behaviour before tests, unless a change is easy and clearly useful.

## 6. Lessons and gotchas (each one cost time)
1. **macOS only shows the camera's infrared stream**; the colour stream the face AI needs is not offered. So the face AI works only on Windows (or Linux). The microphone works on Mac.
2. **Windows `HttpListener` needs admin rights** and fails silently for normal users -> we use a plain loopback `TcpListener` (LocalServer.cs).
3. **`pluginFolderWin: bin`** must be set in `LoupedeckPackage.yaml`, else the plugin never loads on Windows (log stops at "Started loading plugin").
4. **`Assembly.Location` is empty inside the plugin host**: do not read DLL paths; the build time comes from `InformationalVersion` (csproj) via `/health`.
5. A **stale plugin DLL** can keep running after `dotnet build` on Windows (file locked): check `/health` build time (UTC) vs now.
6. **Policy trap:** a trigger can be silently dropped (cooldown 300 s for blink_low in Balanced). Use `--force` to test visuals; read the plugin log.
7. `CoachClient`: repeats are always throttled; `force` means "skip the policy", not "skip the throttle" (a bug here once flooded the plugin and left the owl on screen).
8. **Single noisy EAR frames look like blinks.** First detector would have counted 6 false blinks in 22 s of the real log; the 2-sample + depth rule fixed it.
9. `opencv-python` + `opencv-contrib-python` share the `cv2` folder: removing one breaks the other (happened on the Mac after removing mediapipe). MediaPipe is not needed.
10. macOS: Terminal needs Local Network + Camera permission; permissions are per app, so the Claude app's own shell can't reach the camera.
11. Python 3.14 is too new for the libraries: `brain/.python-version` pins 3.12 (uv installs it).
12. **Camera AI overheats after ~10 min of continuous use**; the blink monitor stops after 8 minutes (`--minutes`). Always-on use needs short bursts (not built).
13. LogiInsight reports **one face per result** only: "person behind" needs our own second-face detection on the colour frames.
14. Keypad redraw ceiling is ~10 fps; haptics have no duration parameter (a long calm buzz = several pulses); haptics exist on the MX Master 4 only.
15. A `PluginDynamicFolder` cannot be opened by code: the user presses the "Coach screen" key once.

## 7. Real-hardware data (Windows, LogiInsight, `brain/ear_log.csv`)
27 face-mesh results/s. Open-eye EAR ~0.25-0.28; blinks dip to ~0.05-0.08 for 110-180 ms (3-5 results). A 6.8 s stretch had no mesh results (cause unknown: looked away/covered?).
Replay: first detector 14 "blinks" (6 false), shipped detector 8, with the 2.5 s limit 10 (adds a 0.6 s slow blink and a 1.7 s eyes-shut).

## 8. Next steps (suggested order)
1. **Pomodoro** (`break_due`): 25 min at the desk; presence + "facing the screen" from the face mesh already received (nose/cheek/iris points -> yaw/pitch), pause after ~30 s without a face or ~60 s looking away, reset after 5 min away. Gaze Tracker (WebSocket :8964, needs calibration) is the accurate alternative.
2. **`speak_up`** (too quiet): the pace code already measures energy; new trigger + pattern + rule + Keypad text.
3. **Person behind**: detect a second face (OpenCV/MediaPipe on the colour frames); outputs already exist (red Keypad warning + knock; meerkat sprite not drawn).
4. **Short-burst camera mode** (AI on ~30 s every 2-3 min) so the camera can run all day.
5. **Settings UI**: a local web page served by the plugin (presets, strength, per-alert on/off, "test buzz") and/or an Options+ Action Editor action (sliders/dropdowns/checkboxes; docs: "Action Editor Actions"; a plugin-wide settings page is not documented).

7. Calibrate pace thresholds with real recordings; collect a Windows pace log like the EAR log.
